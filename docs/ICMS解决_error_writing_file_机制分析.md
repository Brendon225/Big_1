# ICMS 解决 "error writing file" 问题的机制分析

## 一、问题背景

在 ICMS 系统设计之前，Claude Code 经常出现 **"error writing file"** 错误，并陷入死循环：

- 尝试写入文件 → 失败  
- 重试写入 → 再次失败  
- 继续重试 → 持续失败  

无法自动恢复，频率非常高。

---

## 二、ICMS 的解决方案

ICMS 并不是直接修复文件写入的技术问题（如权限、编码等），  
而是通过 **流程规范 + 预防机制**，从根本上减少错误发生的场景。

---

## 三、核心解决机制（三层防护）

### 第一层：任务前强制检查（#140 规则）

**触发时机**：Claude 准备执行任何任务时  

#### 第 0 步：备份检查
- 白名单任务（只读查询） → 跳过  
- 非白名单任务 → 必须执行 `git status`
  - 有未提交更改 → 先 `git commit` 备份
  - 工作区干净 → 继续

#### 第 0.5 步：查询外部记忆（强制）
```bash
curl /api/v1/icms/decisions/search?q=关键词
curl /api/v1/icms/lessons
```

#### 后续流程
1. 识别任务  
2. 记录任务计划（TodoWrite 工具）  
3. 执行任务  
4. 任务完成后记录决策  

**效果**
- ✅ 失败可回滚
- ✅ 中断可恢复
- ✅ 避免重复错误

---

### 第二层：文件操作规范（#136 规则）

#### 创建前必查
- 先搜索是否已有相关文件
- 有 → 迭代（版本号 +1）
- 无 → 新建

#### 存放位置规范
- 文档：`docs/`
- 备份：`backup/`
- 临时：`temp/`
- 配置：`config/`

#### 命名规范
- 文档：`{主题}_{描述}_v{版本}.md`
- 备份：`{type}_backup_{YYYYMMDD}.sql`
- 临时：`temp_{描述}_{YYYYMMDD}.{ext}`

---

### 第三层：大内容处理规范（#107 规则）

**触发条件**：Write/Edit 内容 > 4KB  

❌ 禁止直接 Write  
```python
Write(file_path="large.html", content="...")
```

✅ 强制方案  
```python
content = """超过 4KB 的内容"""
with open("large.html", "w", encoding="utf-8") as f:
    f.write(content)
```

```bash
python create_large.py
```

## 四、实际案例

### 案例 1：SSH 内联 SQL 失败
- 原因：特殊字符
- 方案：SQL 文件 + scp + psql -f

### 案例 2：文件创建位置错误
- 原因：未遵循 #136
- 方案：删除 → 规范重建 / 合并

---

## 五、为什么现在很少出现错误？

| 维度 | ICMS 之前 | ICMS 之后 |
|---|---|---|
| 备份 | 无 | 强制 Git |
| 经验 | 无 | lessons |
| 冲突 | 常见 | 创建前必查 |
| 大内容 | 易失败 | 脚本 |
| 恢复 | 重来 | TodoWrite |

---

## 六、关键洞察

**ICMS 不是修复错误，而是预防错误**

核心理念：
- 先查后做
- 先备份后执行
- 先记录再执行
- 规范操作

---

## 七、总结

ICMS 本质是一套 **防错系统**：
1. 事前预防
2. 事中规范
3. 事后记录
4. 失败保护
